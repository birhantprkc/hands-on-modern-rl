# 16.2 R1-Zero 纯强化学习推理

[16.1](./emergence-and-o1)说明了推理模型怎样进入产品。现在回到训练过程：如果不给模型人工编写的思维链，只提供题目和可以自动验证的答案，强化学习能否让模型学会展开推理？DeepSeek-R1-Zero 用一次公开实验回答了这个问题。

[第 15 章](../chapter18_grpo/grpo-practice-and-mechanism)已经介绍 GRPO、RLVR 与 DAPO。本节不重复算法家族，而是沿着 R1-Zero 的训练线回答四个问题：训练从什么模型和数据开始，GRPO 怎样利用结果奖励更新策略，长推理与自我检查怎样出现，以及纯 RL 为什么仍然需要冷启动与后续对齐。

贯穿本节的是同一道题的反复采样。假设模型面对方程 $x^2-5x+6=0$：有的回答直接猜 $x=2$，有的完整算出 $x=2$ 或 $3$，有的公式正确但代入出错。验证器只检查最终解集，GRPO 再比较同组回答的奖励。随着训练重复进行，能够稳定得到正确结果的推导方式会更常出现。

## 1. 纯 RL 从什么模型开始

要让结果奖励提供信息，训练起点必须已经具备三项条件：模型能理解题目并生成候选解，题目有可靠验证器，同一道题上又能采到有对有错的回答。完全不会解的模型和无法判分的任务，都不能只靠下面这条循环启动。

R1-Zero 从预训练基座模型开始，没有先用人工思维链进行 SFT。训练数据主要是数学、代码和逻辑题；每道题都能通过标准答案、测试程序或规则验证器判断结果。

一次训练包含四步：

```text
从题库采样问题
      ↓
当前模型生成一组回答
      ↓
规则验证器计算正确性与格式奖励
      ↓
GRPO 提高高奖励回答的概率
      └────────────► 下一轮采样
```

这条流程与传统 RLHF 的差别在奖励来源。RLHF 常用从人类偏好训练的奖励模型；R1-Zero 使用可验证奖励，减少奖励模型本身的判断误差。

### 1.1 正确性奖励

数学题可以抽取最终答案并与标准答案比较，代码题可以运行测试。把验证器记为 $v(x,y)$，其中 $x$ 是问题，$y$ 是完整回答，最简单的奖励为：

$$
r_{\text{acc}}(x,y)=
\begin{cases}
1,& v(x,y)=\text{correct},\\
0,& v(x,y)=\text{incorrect}.
\end{cases}
$$

奖励只判断结果，没有指定模型必须使用哪一种解法，也没有提供每一步的标准推理。模型需要在多次采样中找到更容易得到正确答案的行为。

### 1.2 格式奖励

训练还需要把推理部分与最终答案分开，以便验证器稳定抽取答案。格式奖励检查回答是否使用约定的思考与答案标记：

```text
<think>
推理过程
</think>
<answer>
最终答案
</answer>
```

格式奖励解决的是机器解析问题，不能替代正确性奖励。只优化格式会得到结构完整但内容错误的回答。

## 2. GRPO 如何比较同组回答

验证器给出了每条回答的分数，下一步要把“这一组谁更好”变成参数更新。GRPO 使用同一道题各回答之间的奖励差异，因此组内必须同时出现较好和较差的样本。

对同一道题，当前策略生成 $G$ 个回答 $y_1,\ldots,y_G$，验证器分别给出奖励 $r_1,\ldots,r_G$。GRPO 不训练独立 Critic，而是用组内均值和标准差构造相对优势：

$$
\hat A_i=\frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}
{\operatorname{std}(r_1,\ldots,r_G)+\epsilon}.
$$

同组中高于平均奖励的回答得到正优势，低于平均奖励的回答得到负优势。策略更新提高前者的生成概率，并降低后者的概率。PPO 式裁剪限制一次更新的幅度，KL 项则约束当前策略不要在一轮中离参考策略过远。

用四个回答做一个小例子。若奖励是 $(1,1,0,0)$，均值为 $0.5$，标准差也约为 $0.5$，标准化后的优势约为 $(1,1,-1,-1)$。前两个正确回答得到正权重，后两个错误回答得到负权重。若奖励变成 $(1,1,1,1)$，每个回答减去均值后都是 0，这道题在当前批次就不再提供区分信号。公式中的 $\epsilon$ 用来避免标准差为 0 时发生除零。

### 2.1 哪些题目能提供学习信号

如果一组回答全部正确，所有奖励相同，组内优势接近零；如果全部错误，也会遇到同样的问题。有效题目通常处在当前模型有时答对、有时答错的难度区间。

因此，纯 RL 训练还需要管理题目难度：

- 过易题保留少量用于能力回归，大部分降低采样权重。
- 难度适中的题提供主要梯度。
- 过难题需要拆分、补充工具或等待基座模型能力提高。

这与[第 15 章 DAPO](../chapter18_grpo/deepseek-dapo)的动态采样属于同一问题：把计算集中到仍有组内差异的题目上。

## 3. 自我检查如何在训练中出现

组内比较能够提高正确回答的概率，却没有直接写下“请检查计算”这条规则。要理解自我检查为什么出现，需要观察哪些生成行为会让结果奖励更高。

训练早期，回答通常很短，模型经常直接猜测结果。高奖励样本逐渐让策略增加中间推导，因为列出条件、检查计算和尝试替代方法会提高最终答对的概率。

随着训练继续，可以观察到几类行为：

1. **推理链变长**：模型在给答案以前展开更多中间步骤。
2. **重新检查**：模型回看前面的计算，发现矛盾后修改结论。
3. **切换方法**：当前路线无法继续时，转向另一种证明或算法。
4. **自我验证**：把得到的答案代回条件，检查是否满足题目。

这些行为没有逐步标签，却受到最终正确性奖励的间接选择。某种行为只要持续提高成功率，就会在后续采样中更常出现。

### 3.1 怎样理解 Aha Moment

R1-Zero 报告中的 Aha Moment 指模型在一段推理中主动停下来检查，并写出类似“换一种方法重新验证”的内容。它说明结果奖励可以强化反思行为，但不能证明强化学习从零创造了推理能力。

基座模型已经通过预训练见过证明、代码调试和自我修正文本。纯 RL 的作用是让这些潜在行为更稳定地服务于可验证任务。[16.1](./emergence-and-o1)因此区分了能力涌现与能力激活。

## 4. 为什么还需要冷启动和对齐

结果奖励回答了“答案是否通过验证”，没有回答“推理是否易读、长度是否合适、开放问题是否有帮助、工具使用是否安全”。因此，R1-Zero 是一次训练机制实验，还不是完整的产品后训练流程。

R1-Zero 展示了不依赖人工思维链也能强化推理，但公开结果同时暴露了纯 RL 的边界：

- 推理链可能混合多种语言，阅读体验不稳定。
- 回答会为了提高正确率不断变长，增加延迟和成本。
- 格式可能漂移，使答案抽取和工具协议失效。
- 规则奖励只覆盖可验证任务，不能直接处理写作、帮助性与安全偏好。
- 验证器存在漏洞时，模型可能学会利用规则而没有提高真实能力。

完整的 DeepSeek-R1 因此增加冷启动 SFT、推理 RL、拒绝采样和通用对齐阶段。冷启动样本负责建立可读格式与基本行为，纯 RL 继续提高可验证任务能力，后续数据回流和对齐再修正语言、风格与安全问题。

## 本节小结

- R1-Zero 从基座模型直接进行强化学习，训练信号来自可自动验证的正确性奖励与格式奖励。
- GRPO 用同一道题的一组回答估计相对优势，省去独立 Critic。
- 长推理、反思、方法切换和自我验证会因为提高最终成功率而得到强化。
- 纯 RL 仍然存在可读性、长度、通用能力与奖励漏洞问题，因此完整训练需要冷启动、数据回流和后续对齐。
